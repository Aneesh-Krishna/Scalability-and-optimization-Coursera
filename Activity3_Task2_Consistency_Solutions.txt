================================================================================

the same on every server, while keeping the speed benefits of caching.

HOW THE SOLUTIONS WORK TOGETHER
-------------------------------

1. Editor saves an article -> write-through updates the database and Redis.
2. A Pub/Sub event and a CDN purge are sent so every server, region, and
   edge location drops the old version immediately.
3. Version numbers make sure a late or duplicate update cannot bring back
   older content.
4. The next reader triggers a read-through refill, with a lock so only one
   request rebuilds the entry.
5. Short TTLs act as a safety net in case any invalidation message is lost.
6. Comments and trending topics use real-time streams and one shared Redis
   cluster, so all users see the same live data within a second.
