TASK 1: SELECT THE BEST EXPIRATION STRATEGY - BANKING SYSTEM
============================================================

Scenario: A banking system caches data to improve performance and security.
Each dataset changes at a different rate and carries a different level of
risk, so each one needs its own expiration policy.


EXPIRATION STRATEGIES USED
--------------------------

- Absolute Expiration: The item is removed at a fixed time or after a fixed
  duration, regardless of how often it is used.
- Sliding Expiration: The timer resets every time the item is used, so the
  item expires only after a period of inactivity.
- Dependent Expiration: The item stays in the cache until the data it
  depends on (e.g., a database record) changes, then it is cleared.

SUMMARY OF THE THREE REQUIRED DATASETS
--------------------------------------

1. User Authentication Tokens -> Absolute Expiration
   Security comes first. A fixed lifetime limits how long a stolen token can
   be used, and a short idle timeout inside that limit protects unattended
   sessions.

2. Transaction History -> Dependent Expiration
   Old transactions never change, so the cache is refreshed only when a new
   transaction is posted. This keeps the history accurate while avoiding
   unnecessary database queries.

3. Live Exchange Rates -> Absolute Expiration (very short TTL)
   Rates change constantly, so a very short fixed lifetime, plus refreshing
   when the rate feed sends a new value, keeps them current. Many users still
   share one cached value, which reduces load on the rate provider.


SECURITY AND RELIABILITY RULES
------------------------------

- Never cache card numbers, PINs, or passwords.
- Encrypt cached sensitive data and keep the cache on a private network.
- Always confirm balances and exchange rates against the source of truth
  before money moves; the cache is only used for display.
